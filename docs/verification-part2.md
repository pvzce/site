## 发现、修复并重测的问题

- 流式 multipart 同时携带 CSRF 请求头时，原中间件跳过表单解析，导致上传处理器没有 Reader。现统一验证首个 CSRF 字段并保留流；已有 CSRF/跨站测试新增请求头场景，真实反馈附件普通表单重测通过。
- Docker 构建期间环境磁盘耗尽，S3 没有可用数据节点，真实上传超时，S3 集成失败。清理可回收构建缓存后恢复并完整重测，未删除用户数据/存储卷。
- 同一次磁盘故障使 ClamAV 记录临时目录错误却对 EICAR 返回 clean。现 clean 结果必须通过同服务的 EICAR 检测探针；专门模拟“全部返回 OK”的降级扫描器，断言 failed。扫描容器新增独立 1 GiB tmpfs，配置为单扫描线程。真实 clean/EICAR、隔离与 E2E 重测通过。扫描器重建的启动窗口曾导致一次连接重置；待健康后重测通过，没有放宽安全断言。

以上中间失败均已修复/恢复并重新通过；最终本地检查没有遗留失败。GitHub CI 由提交后的正常 PR 检查记录提供，以实际状态为准。
